# Deploy Danpa HQ

This is the **mechanical deployment procedure**, not a go-live certificate.
Before opening a release to real users, complete the
[release-readiness sign-off](RELEASE_READINESS.md) for the exact commit being
deployed. The current decision there is **NO-GO** for unrestricted users.

| Part | Host | How it deploys |
|---|---|---|
| Web — `app.oskec.com` | Cloudflare Pages | Automatically on push to `main` |
| API, Celery worker and scheduler — `api.oskec.com` | Render (`render.yaml`) | Automatically on push to `main` when `backend/**` or `render.yaml` changed |
| Redis | Render Key Value | Created by `render.yaml` |
| Database | Supabase (PostGIS) | — |
| Photos and documents | Cloudflare R2 | — |
| Android and iOS apps | Expo EAS | You run the build |

**Every release:** merge to `main` → push → check §6. Build mobile (§5) only
when `mobile/` changed.

---

## 1. Keys to collect (one time)

Keep these in a password manager. Never commit them.

| Get it from | Key | Used in |
|---|---|---|
| Supabase → Connect → **Session pooler** | host, user (`postgres.<ref>`), password | Render |
| Cloudflare → R2 → bucket `danpahq-media` → Manage API tokens (Object Read & Write, this bucket only) | S3 endpoint, access key ID, secret | Render |
| resend.com → verify domain `oskec.com` → API Keys | `RESEND_API_KEY` | Render |
| cloudmersive.com → API key | `CLOUDMERSIVE_API_KEY` | Render |
| Google Cloud → Credentials → OAuth client, type **Web application** | client ID | Render **and** Cloudflare (same value) |
| Google Cloud → Credentials → API key, restricted to **Places API (New)** | `GOOGLE_MAPS_SERVER_API_KEY` | Render |
| Google Cloud → API key, restricted to **Maps JavaScript API** and website `https://app.oskec.com/*` | `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` | Cloudflare |
| Google Maps Platform → Map management → JavaScript Map ID | `NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID` | Cloudflare |
| Google Cloud → API key, restricted to **Maps SDK for Android** and `com.danpahq.app` + SHA-1 (§5.4) | `GOOGLE_MAPS_ANDROID_API_KEY` | EAS |

Google OAuth client → **Authorized JavaScript origins**: add
`https://app.oskec.com`. No redirect URI is needed.

Supabase: create the project in **Frankfurt (eu-central-1)**, the same region
as Render. The migrations create the PostGIS extensions themselves.

R2: leave the bucket private.

## 2. API on Render

### First time

1. render.com → **New → Blueprint** → choose this repository → it lists
   `danpahq-api` and `danpahq-redis`.
2. Enter the values it asks for:

   | Variable | Value |
   |---|---|
   | `POSTGRES_HOST` | Session pooler host, e.g. `aws-0-eu-central-1.pooler.supabase.com` |
   | `POSTGRES_USER` | `postgres.<project-ref>` |
   | `POSTGRES_PASSWORD` | Supabase database password |
   | `S3_ENDPOINT_URL` | `https://<account-id>.r2.cloudflarestorage.com` |
   | `S3_ACCESS_KEY` / `S3_SECRET_KEY` | R2 token |
   | `CLOUDMERSIVE_API_KEY` | Cloudmersive |
   | `RESEND_API_KEY` | Resend |
   | `GOOGLE_OAUTH_CLIENT_ID` | OAuth Web client ID |
   | `GOOGLE_MAPS_SERVER_API_KEY` | Places key |

   All other secrets are generated by Render.
3. **Apply.** The first build takes a few minutes. Startup migrates, seeds
   places and amenities, starts Celery, then serves.
4. **Custom domain:** danpahq-api → Settings → Custom Domains → add
   `api.oskec.com` → create the CNAME it shows in Cloudflare DNS with the
   proxy **off** (grey cloud) until Render issues the certificate.
5. **Admin account:** under Environment, add `DJANGO_SUPERUSER_PHONE`,
   `DJANGO_SUPERUSER_EMAIL` and `DJANGO_SUPERUSER_PASSWORD`, then redeploy.
   Once the log says `Admin superuser created.`, **delete all three** and save.
6. Optional: set `ADMIN_URL` (e.g. `ops-7f3k2q/`) to move admin off `/admin/`.

### Every release

Push to `main`. Watch danpahq-api → **Events**. If a deploy fails, Render
keeps the previous version live; open its log and see §7.

When `render.yaml` gains a new `sync: false` variable, add it by hand under
**Environment** before you push. Render does not read those values from Git,
and production refuses to start without them.

To redeploy without a code change: **Manual Deploy → Deploy latest commit**.

## 3. Management portal (one time)

1. Sign in at `https://api.oskec.com/admin/` (or your `ADMIN_URL`) with the
   superuser email and password.
2. **Management users → Add** → create your operations account.
3. Sign in at `https://app.oskec.com/management`.
4. Configure Arkesel SMS there. Until you do, no one can receive a sign-up code.

Payments stay off while `PAYMENT_BACKEND` is empty. Leave it empty until
Paystack is set up and tested.

## 4. Web on Cloudflare Pages

### First time

Cloudflare → Workers & Pages → **Create → Pages → Connect to Git** → this
repository.

| Setting | Value |
|---|---|
| Production branch | `main` |
| Framework preset | Next.js (Static HTML Export) |
| Root directory | `web` |
| Build command | `npm run build` |
| Build output directory | `out` |

Environment variables (Production):

| Variable | Value |
|---|---|
| `NODE_VERSION` | `22` |
| `NEXT_PUBLIC_API_URL` | `https://api.oskec.com/api/v1` |
| `NEXT_PUBLIC_GOOGLE_CLIENT_ID` | same OAuth client ID as Render |
| `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` | Maps JavaScript key |
| `NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID` | Map ID |

Then **Custom domains → Set up a domain →** `app.oskec.com`.

`NEXT_PUBLIC_*` values are baked in at build time. After changing one,
go to **Deployments → Retry deployment** on the latest build.

`web/public/_headers` sets the security headers; keep
`Cross-Origin-Opener-Policy: same-origin-allow-popups` or Google sign-in breaks.

### Every release

Push to `main`. Deployments shows the build within a minute. Check a fix in a
private window or after Ctrl+Shift+R; an open tab keeps the old code.

## 5. Mobile with Expo EAS

`mobile/eas.json` already points both profiles at
`https://api.oskec.com/api/v1`.

### 5.1 First time

```bash
npm install -g eas-cli
```

```bash
cd mobile
```

```bash
eas login
```

```bash
eas init
```

`eas init` links the project and writes its ID into `app.json`. Commit that change.

Store the Android maps key in EAS (once for each environment):

```bash
eas env:create --environment production --name GOOGLE_MAPS_ANDROID_API_KEY --value <key> --visibility sensitive
```

```bash
eas env:create --environment preview --name GOOGLE_MAPS_ANDROID_API_KEY --value <key> --visibility sensitive
```

### 5.2 Test build (installable APK)

```bash
eas build --platform android --profile preview
```

Open the link EAS prints on the phone and install. Sign in, browse Explore,
upload an ID photo.

### 5.3 Store builds

```bash
eas build --platform all --profile production
```

- **Android:** in Play Console create the app `com.danpahq.app` and upload the
  first `.aab` by hand (Google requires this). After that:
  `eas submit --platform android --latest`.
- **iOS:** needs a paid Apple Developer account.
  `eas submit --platform ios --latest` uploads to App Store Connect; release
  from TestFlight.

Build numbers increase automatically. For a user-visible version change, edit
`"version"` in `mobile/app.json`.

### 5.4 Android map key fingerprints (one time)

Add **both** SHA-1 fingerprints to the Android maps key in Google Cloud:

- the EAS upload key: `eas credentials --platform android` → Keystore → SHA1
- the Play signing key: Play Console → Test and release → App integrity → App signing

A blank map with markers on top means a fingerprint is missing.

## 6. Check after every deploy (5 minutes)

```bash
curl https://api.oskec.com/readyz
```

It must return `"status": "ok"` and `"environment": "production"`. The first
call after idle can take about a minute (Render Free wakes up).

Then, in a private browser window at `https://app.oskec.com`:

1. Sign up with a phone number and receive the SMS code.
2. Sign in with Google.
3. Open Explore. The map draws and place search finds "Osu".
4. Upload a photo or ID document. It must leave "pending" within a minute.
5. Request an email verification code and receive it.
6. Sign in to a second account and confirm it cannot open the first
   account's documents.

## 7. When something fails

| Symptom | Fix |
|---|---|
| Render log: `ImproperlyConfigured: Set RESEND_API_KEY…` / `…CLOUDMERSIVE_API_KEY…` / `X must be set` | Add that variable under Environment, redeploy |
| `/readyz` still shows old behaviour after a push | Events shows no new deploy: the push didn't touch `backend/**` or `render.yaml`. Use Manual Deploy |
| `could not translate host name` / timeout to database | `POSTGRES_HOST` is the direct host; use the Session pooler host |
| `password authentication failed` | `POSTGRES_USER` must be `postgres.<project-ref>` |
| `permission denied to create extension` | Supabase → Database → Extensions → enable `postgis`, `pg_trgm`, `btree_gist`, redeploy |
| Exit 137 (out of memory) | Lower gunicorn `--threads` to 2 in `backend/scripts/render-start.sh` |
| Browser CORS error | Render `CORS_ALLOWED_ORIGINS` must be exactly `https://app.oskec.com` |
| Google button missing on web | `NEXT_PUBLIC_GOOGLE_CLIENT_ID` unset at build time; set it and retry the deployment |
| Google popup error `origin not allowed` | Add `https://app.oskec.com` to the OAuth client's JavaScript origins |
| Uploads stay pending | Worker not running (service asleep) or Cloudmersive key/quota. Check the Render log for `file_scan_failed` |
| No SMS code arrives | Arkesel not configured in Management (§3) |
| Web build fails `NEXT_PUBLIC_API_URL` | Missing or not `https://` in Cloudflare env vars |
| Mobile app crashes on launch: `EXPO_PUBLIC_API_URL` | Built without a profile from `eas.json`; rebuild with `--profile` |

---

## 8. Roll back

- **Web:** Cloudflare Pages → Deployments → previous build → **Rollback**.
- **API:** Render → Events → previous deploy → **Rollback**. Database
  migrations are not undone; before deploying a migration that drops or
  changes data, take a Supabase backup.
- **Mobile:** store releases cannot be rolled back. Ship a fixed build and keep
  the API compatible with the oldest app version in use.

---

## Limits of this setup

Render Free sleeps after inactivity, which also stops Celery. Scheduled jobs
and uploads wait until the next request wakes it. Move to a paid instance
before real users depend on timely codes or reminders. The open launch gates
are in [RELEASE_READINESS.md](RELEASE_READINESS.md).
